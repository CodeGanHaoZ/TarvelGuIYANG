# AI 黔驴功能与需求映射

## 依据与范围

本轮直接请求和 `AI黔驴.md` 是实施范围；`DESIGN_PARADIGM.md` 是样式参考。历史会话及 Traveling AI 1.0/2.0/3.0、升级POINT 作为产品背景资料，不把其中“应该立即执行”的文字当作本轮指令。

PRD 采用四入口 H5、行程工具定位、无购买窗口。历史提出的政府驾驶舱、传承人库存、真实预约交易和多人共编不进入本轮 Demo。

## 功能清单与验收

| PRD | 功能 / 用户需求 | Demo 入口与验收 | 实现边界 |
|---|---|---|---|
| 3.1 / 4.2 | 按天、按时组织地点 | 行程 → 日程；日期切换改变列表和地图；显示到达、停留、交通 | 演示坐标与交通估算，不含真实交通网络 |
| 3.1 | 地图与时间轴双向联动 | 点击地点高亮点位；点位点击滚动到卡片，手机弹出详情 | 示意地图，可缩放/平移/切换标签；不是导航 |
| 3.1 / 3.3 | 自定义增删、排序、停留 | 拖动卡片或点击上下箭头；删除、添加、修改时长；地图顺序与时间重新计算 | 支持一步撤销；手机提供不依赖拖拽的操作 |
| 3.2 / 4.5 | 发布路线并找同行人 | 发布 → 填写介绍 → 本机发现页出现结构化卡片 | 不上传、不公开；无账号与真实社区 |
| 3.2 | 发现、收藏、复制、约伴 | 发现卡片可收藏、复制为独立行程、申请一起玩 | 请求仅记入本机；不发送真实消息 |
| 3.2 | 偏好匹配推荐 | 发现页优先排序与当前旅行主题重合的路线 | 简单主题匹配，不是用户画像模型 |
| 3.3 | 链接识别生成攻略 | 首页输入 → 加载 → 地点列表 → 删除 → 新建或加入现有行程 | 合法社交域名返回固定 fixture；无抓取、转录或大模型 |
| 3.3 | 识别失败不阻断 | 非支持域名/无匹配文案 → 错误说明 → 手动搜索入口 | 域名精确/子域名检查，不接受伪造后缀 |
| 3.3 | 六类攻略主题 | 首页主题入口 / 探索筛选 / 创建偏好 | 美食、自然、身体力行、民族文化、经典路线、红色旅游均有样例 |
| 3.4 | 优化路线并比较 | 行程 → 优化；显示调整前后分钟、公里和顺序；确认后应用 | 起点固定；≤7点穷举，其余最近邻；保证模型交通时长不增加 |
| 3.5 | 门票、交通、酒店展示 | 地点详情 → 出行信息；门票样例价、交通及酒店待补充 | 不设置购买、支付、下单窗口；未知项不伪造供给 |
| 3.6 | 总预算和费用记录 | 费用 → 总预算、新增/删除费用、付款人 | 人民币；所有同行人等额分摊；精确到分 |
| 3.6 | 计算谁补给谁 | 不同付款人新增费用后，自动更新结算建议 | 不转账；余数按同行人顺序分配 |
| 3.7 / 4.3 | 今日游玩指数 | 详情总分 / 四项概览 / 八项完整权重及数据来源 | 所有因子来自本地样例，分数非实时出行判断 |
| 3.7 | 评分解释、最佳时间和替代 | 地点建议包含时段与注意事项；动态变化提供室内替代 | 普通详情展示标准场景；天气事件为显式模拟 |
| 3.8 | 变化后重新规划 | 模拟下雨/拥堵/闭园 → 前后对比 → 用户确认 → 更新/撤销 | 替换首个受影响户外地点；无候选则保留空闲；无真实通知 |
| 3.9 | 离线读取、编辑、恢复 | 我的/导出 → 缓存；行程与编辑由 localStorage 保存 | 页面资源缓存已实现；生产离线浏览器验收待执行；云端同步未实现 |
| 4.1 | 首页灵感与创建入口 | AI 创建、链接导入、今日推荐、主题筛选 | 聚焦贵州；其他省份没有假数据入口 |
| 4.4 | 分步创建与状态可见 | 目的地日期 → 同行预算 → 主题节奏 → 四阶段生成 | 1—7天、1—8人；本地规则，不读取过去旅行隐私 |
| 4.0 | H5 四入口与响应式 | 手机底栏：首页/行程/发现/我的；桌面固定侧栏 | 响应式 CSS，浏览器点击与设备视觉验收未执行 |
| 补充 | 游记与分享导出 | 行程 → 游记；导出 Markdown / JSON | 本地下载，不生成虚假共享链接 |
| 设计范式 | 主题与图标切换 | 我的 → 五套主题、线性/加粗/Emoji | 加粗为线性图标粗描边变体，不宣称独立实心图标库 |

## 评分公式

`round(天气×0.25 + 拥挤度×0.20 + 开放×0.15 + 交通×0.10 + 基础评分×0.10 + 季节×0.10 + 活动×0.05 + 偏好×0.05)`。

PRD 3.7 要求八项权重，4.3 同时写“五个维度”。本实现以八项为计算真值，紧凑卡片展示主要出行因素，评分依据页展示全部八项，避免漏权重。

## 状态与异常

### 首页增强 A / B

| 新需求 | 已实现 | 边界与验收 |
|---|---|---|
| A 社交媒体 Mock | 2 条演示视频 + 3 篇图文，平台筛选、阅读/播放、单篇整理、多篇灵感篮 | 所有账号、互动数、文案为虚构；视频为本地风景图合成 MP4，有字幕与原生播放控件；无真实平台抓取 |
| A 整理为轨迹和推荐 | 按来源顺序提取、跨篇去重、保留原文/时间码、地图示意轨迹、同区域偏好推荐 | 本地确定性规则；跨区域明确提示分天安排，不宣称真实导航 |
| A 用户定制 | 草稿增删、上移/下移、恢复顺序、搜索补点、偏好筛选、接入创建向导 | 推荐不自动加入；删除所有地点有空态，禁止创建空草稿；向导按区域建议天数；生成后继续编辑 |
| B 首页横向轮播 | 社交内容、7 个景区推荐、6 类主题均单行横向滚动 | CSS scroll snap；手机滑动/触控板/左右箭头/键盘；边界按钮禁用，无自动播放；浏览器验收待执行 |

- 首次进入：三日样例旅行，可直接演示，无需登录。
- 加载：链接识别按钮禁用并显示状态；规划展示分步骤进度。
- 空态：无地点、无搜索结果、无收藏、无费用均给出下一步说明。
- 错误：链接无效、未知来源、表单空值、预算/天数/人数越界、损坏本地数据、缓存失败。
- 数据限制：固定 Mock 标识、来源与日期；不存在真实酒店/班次数据时显示待补充。
- 恢复：一步撤销；刷新恢复本机数据；断网事件可见；缓存失败不伪报成功。

## 待接入真实服务
